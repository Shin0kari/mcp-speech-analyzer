# План реализации

## Решения

- Ответы и интерфейс на русском.
- Локальное распознавание, без отправки аудио в облако.
- Сохранение аудио — настройка, по умолчанию выключена; текст сохраняется полностью.
- Первый проверенный backend: Codex `gpt-6.1-terra`, отдельный app-server stdio. Контекст пользователя передаётся явно.
- Кандидат для desktop-оболочки: C# / WPF на установленном .NET, с проверкой минимальной сборки. Для STT сначала проверить runtime и измерить скорость, затем выбирать модель. Наличие GPU не является бенчмарком.

## Этапы и критерии готовности

1. **Связь с моделью — проверен резервный путь.** См. `codex-investigation.ru.md`. Общий desktop-чат и скрытие фоновых ходов не подтверждены.
2. **UI и симуляция — реализованы.** Отдельный модуль состояния, виртуальные часы и имитаторы модели/STT. Граница клика, ожидание pending по обоим каналам, сброс таймера, объединение событий и сериализация покрыты сценарными тестами. UI явно обозначает симуляцию. Результаты и ограничения: `simulation-stage.ru.md`.
3. **Реальный звук.** Микрофон плюс process loopback, независимые метры и состояния. Выбор процесса с дочерними, исчезновение источника. Проверка на целевом приложении пользователя.
4. **Русский STT.** Локальный runtime, предварительный/окончательный текст, flush до границы клика, ограниченная очередь аудио, статус отставания. Измерить задержку двух каналов. Временные буферы очищаются при выключенном хранении.
5. **Модель и вопросы.** Инкрементальный текст, проверяемая схема состояния, история вопросов и подавление дублей. Отдельно проверить сбой после ответа до фиксации состояния.
6. **Хранение и MCP.** Транзакционные границы, восстановление, исходный текст, настройки и контекст. MCP предоставляет управление захватом, status, transcript, questions, analysis state, context. Подключение не стартует запись.
7. **Длительная сессия.** Длинные разговоры, compaction, точные цитаты/числа после восстановления, ограничение памяти и очередей, сохранение прокрутки.

Полное задание: `product-spec.en.md`. Этап завершается только после воспроизводимой проверки; частичные результаты явно обозначаются.

## Реализованный этап: окно и планировщик на имитации

Этот этап следует за диагностикой подключения и короткой проверкой Brave. Реальный звук пока остаётся в отдельной диагностической утилите. Следующая задача — подключить к окну реальный микрофон и process loopback Brave, сохранив имитатор для регрессионных проверок.

1. Создать минимальную WPF-оболочку и отдельную библиотеку логики. UI не должен владеть таймерами и обработкой состояния модели.
2. Определить контракты `ITranscriptSource`, `IModelBackend`, `IConversationStore` и управляемые часы. Сегменты имеют стабильный ID, роль канала, время начала/конца и статус предварительный/окончательный. Готовность транскрипции подтверждается отдельно для каждого канала.
3. Реализовать имитатор с двумя каналами, задержкой финализации и настраиваемой задержкой/ошибкой модели. Название режима «Симуляция» постоянно видно. Результаты имитатора не выдаются за ответы Terra.
4. Реализовать один обработчик операций состояния. Таймер хранит срок следующего запуска; клик обновляет его немедленно, фиксируя границу. Параллельный анализ не запускается; повторные клики объединяются, ожидающие события не образуют неограниченную очередь.
5. Разделить границу аудио, готовность транскрипции обоих каналов и успешно сохранённую границу анализа. Не продвигать последнюю при сбое. Предварительный текст не включать в завершённый анализ.
6. Показать историю ответов, расшифровку, статусы, переключатель ручного/автоматического режима, поле запроса, fallback-инструкцию и обратный отсчёт. Старт окна не запускает даже имитацию записи.
7. Проверить сценарии виртуальными часами и управляемыми ответами имитаторов. Только затем подключать реальный аудиозахват вместо имитатора.

### Условия завершения ближайшего этапа

- Окно запускается локально, симуляция начинается отдельной кнопкой; есть пауза, продолжение и остановка.
- При тишине нет модельных вызовов. Ручной таймер — 60 секунд, автоматический — около 5 секунд, без перекрытия операций состояния.
- После успешного анализа на отметке 60 секунд и клика на отметке 80 секунд обрабатывается только остаток до 80; следующий фон назначается на 140 секунд независимо от длительности ответа.
- Клик ждёт pending-транскрипцию до своей границы по обоим каналам; речь после неё не попадает в этот ответ.
- Работающий фон повторно не анализируется после успешного сохранения; при сбое повтор сохраняет все сегменты и не создаёт дубли ответов.
- Серия кликов и тиков создаёт ограниченное число ожидающих операций. Ошибки не блокируют UI и не теряют текст.
- При чтении истории новые сообщения не сдвигают прокрутку; есть возврат к последнему сообщению.

## Публикация проекта

Пользователь запросил приватный репозиторий GitHub. В него включаются исходники, правила, исходное задание и документация. Локальные отчёты `artifacts/`, сборки, модели STT, записи, БД и секреты исключены через `.gitignore`. Данные реальных разговоров в репозиторий не добавляются. Публикация проекта не означает готовность приложения: текущая стадия явно указана в README.
