# Проверка звука Brave — 28 октября 2026

Пользователь указал открытую вкладку Brave с включённым звуком. Для предварительной проверки аудио API создана отдельная консольная утилита `tools/ProcessAudioProbe`. Она не заменяет следующий плановый этап UI/планировщика на симуляции.

## Подтверждено локально

- Найден основной процесс Brave, PID на момент проверки: `12884`.
- Его дочерний процесс Audio Service: `30736`; также обнаружены renderer и другие дочерние процессы. Адреса и содержимое вкладок не читались.
- Применён Windows `ActivateAudioInterfaceAsync` с `AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`, PID основного Brave и `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE`.
- Первый запуск диагностического кода вернул `0x8000000E`. После исправления видимости COM callback и `IAgileObject` для COM повторный запуск завершился успешно.
- Шестисекундный тест: PCM 44 100 Гц, 16 бит, 2 канала; 264 159 аудиокадров; 262 836 кадров в пакетах с пиком выше 0,0001; 0 флагов discontinuity.
- Максимальный пик: `0.105530`, общий RMS: `0.011161`. Ненулевой сигнал подтверждён.
- PCM использовался только в оперативной памяти для расчёта уровня и очищался после обработки. Утилита не создаёт аудиофайлы, не распознаёт текст и не отправляет данные в сеть.
- Сборка на установленном .NET SDK: успешно, 0 предупреждений и ошибок.
- Повторный шестисекундный тест финальной сборки после доработки срока жизни параметров COM также успешен: 264 159 кадров, 0 discontinuity, пик `0.095490`, RMS `0.009900`.

Два канала PCM здесь означают стерео Brave, а не две независимые роли «Вы»/«Собеседник». Микрофон этим тестом не захватывался.

## Ограничения

Проверено дерево браузера, а не отдельная вкладка. Другие воспроизводящие вкладки этого экземпляра Brave могут попасть в тот же поток. Связь renderer PID с конкретной вкладкой не устанавливалась. Отдельный Audio Service — наблюдение о текущем запуске, а не гарантия постоянных PID.

Не проверены: изоляция звука относительно одновременно звучащего постороннего приложения, поведение при закрытии/перезапуске Brave, устойчивость длительного захвата, выбор устройства микрофона, STT и тайминг транскрипции. Утилита завершает тест при исчезновении целевого процесса; автоматическое переподключение пока не реализовано.

На машине build 26200. Microsoft указывает build 20348 для перечисления process loopback, а страница ActivateAudioInterfaceAsync приводит 20438 в описании параметров. На более старые сборки вывод из этой проверки не переносится.

## Повторение

```powershell
dotnet build tools/ProcessAudioProbe/ProcessAudioProbe.csproj --ignore-failed-sources
dotnet tools/ProcessAudioProbe/bin/Debug/net8.0-windows/ProcessAudioProbe.dll --pid <актуальный-PID-Brave> --seconds 6
```

Без явных аргументов утилита выводит справку и не активирует захват. Допустимая длительность — 1–30 секунд. PID необходимо заново определить после перезапуска браузера. Диагностику запускать обычным пользовательским процессом Windows с доступом к аудио.
