# MCP Speech Analyzer

Windows-приложение для двухканальной расшифровки русской речи и помощи через Codex. Готово окно WPF с имитацией расшифровки и модельных ответов, отдельным планировщиком и сценарными тестами. Реальный двухканальный захват, STT, подключение модели к окну, сохранение между запусками и MCP-сервер — следующие этапы.

## Запуск окна

Нужен Windows x64 с .NET SDK 8 или новее и поддержкой сборки WPF. На машине разработки проверен SDK 10.0.401, приложение нацелено на .NET 8. Для запуска собранного exe нужен .NET 8 Desktop Runtime.

```powershell
dotnet run --project src/SpeechAnalyzer.Desktop/SpeechAnalyzer.Desktop.csproj
```

Либо запустите `scripts/run-desktop.ps1` из PowerShell. Открытие окна не запускает симуляцию: нажмите «Старт». Демонстрационные реплики появляются раз в 6 секунд, окончательный текст — через 1,5 секунды. Переключите режим или нажмите «Ответить». На вкладке «Расшифровка» можно добавить свою тестовую реплику.

В окне постоянно виден режим «СИМУЛЯЦИЯ». Микрофон и Brave не захватываются, запросы Codex не отправляются, смысл тестовых реплик размечен заранее. Данные этого этапа хранятся только в памяти до закрытия окна.

## Проверки

```powershell
dotnet build SpeechAnalyzer.sln
dotnet run --project tests/SpeechAnalyzer.Core.Tests/SpeechAnalyzer.Core.Tests.csproj
```

Или `scripts/check.ps1`: сборка решения, сценарные тесты и проверка синтаксиса диагностических Node.js-скриптов. `dotnet test` для текущего автономного runner не используется. Тесты и окно не требуют подключения к Codex; Node.js нужен только для проверки/запуска диагностических скриптов.

## Уже проверено

Отдельный `codex app-server --stdio` работает с `gpt-6.1-terra`: получены потоковые ответы, контекст восстановлен после запуска нового процесса. Подключение к существующему desktop-чату пока не подтверждено.

## Диагностика

Нужны Node.js 24 и установленный авторизованный Codex CLI в PATH. Сторонние npm-пакеты не требуются.

```powershell
node scripts/probe-codex.mjs standalone
```

Для проверки общего сокета используйте `proxy`. Для двух модельных запросов и проверки восстановления: `node scripts/verify-codex-session.mjs`. Эта команда создаёт постоянную тестовую сессию и расходует лимиты Codex. Ограничения и подробности — в отчёте диагностики.
